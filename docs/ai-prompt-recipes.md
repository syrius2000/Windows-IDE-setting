# 統計・RWD初心者向け Cursor AI プロンプトレシピ集

この文書は、Cursor Proを使って統計解析やRWD作業を始める人向けの、コピーして使える依頼文集です。最初は`data/synthetic/`の合成データだけを使い、AIが作ったコードを必ず自分で実行・確認してください。

## 1. 使い方の基本

良い依頼文は、次の順序で書きます。

```text
目的 → 使用データ → 使用言語 → 欲しい出力 → 検証条件 → 禁止事項
```

依頼前に次を確認します。

- 実患者データ、個人情報、自由記載、認証情報をCursorへ貼り付けない
- まず`data/synthetic/`の合成データでコードを作る
- 使用するデータの列名、単位、欠測値コード、解析対象集団を明示する
- AIの回答をそのまま採用せず、実行結果・統計量・図・ログを確認する
- 解析計画、研究目的、臨床的な解釈と矛盾しないか人がレビューする

## 2. 共通の前置き

各レシピの先頭に、次の安全な前置きを追加して使えます。

```text
このプロジェクトの data/synthetic/ にある合成データだけを使ってください。
実データ、個人情報、認証情報を読み込むコードや外部送信処理は作成しないでください。
使用した列、除外条件、欠測値の扱い、統計手法の前提を説明し、実行可能なコードと検証方法を提示してください。
```

## 3. 生存時間解析

### 3.1 RでKaplan-Meier曲線とLog-rank検定

```text
data/synthetic/ の合成データを用いて、生存時間解析を行うRコードを書いてください。
生存時間列は time、イベント列は status、群変数は group と仮定します。
列が存在しない場合は、実際の列名を先に確認してからコードを提案してください。
Kaplan-Meier曲線、リスク集合表、中央値生存時間、95%信頼区間、Log-rank検定を出力してください。
欠測値の除外件数と解析対象数を表示し、合成データでの実行確認方法も示してください。
```

### 3.2 PythonでCox比例ハザードモデル

```text
data/synthetic/ の合成データを用いて、PythonのlifelinesでCox比例ハザードモデルを作成してください。
time、status、group、ageを使用し、groupとageのハザード比、95%信頼区間、p値を表にしてください。
比例ハザード性の確認方法、欠測値の扱い、イベント数と説明変数数の妥当性を説明してください。
統計的に有意という表現だけでなく、効果量と不確実性を解釈する注意点もコメントしてください。
```

## 4. データ品質監査

```text
data/synthetic/ のテーブルについて、データ品質監査用のコードを作成してください。
列ごとの型、ユニーク数、欠測率、範囲、重複行、日付の前後関係を確認してください。
欠測率パターンを可視化し、MCAR/MARの可能性について「データだけでは断定できない」ことを明記してください。
IQRまたは頑健な方法で異常値候補を検知し、候補の理由と確認すべき業務ルールを一覧にしてください。
監査結果は個票を出力せず、件数と集計値だけを保存してください。
```

## 5. 開示統制・小セルマスキング

```text
合成データから作成した集計表に対して、セル数が5例未満の箇所をハイフン（-）に置換するコードを書いてください。
マスキング後の分母を用いてパーセンテージを再計算し、丸めによる合計不一致も検査してください。
行・列合計から少数セルが推測できる差分開示のリスクも確認してください。
個票、識別子、自由記載は出力せず、マスキング前後の集計表と検査ログだけを outputs/private/ に保存してください。
公開前に release-manifest.yml の人手レビューが必要であることを、コードのコメントと実行結果に明記してください。
```

## 6. 医師・臨床家向けの解説

```text
以下の統計結果を、医師・臨床家向けに平易な日本語で要約してください。
ハザード比、95%信頼区間、p値、解析対象数、イベント数を正確に記載し、臨床的な意味と統計的不確実性を分けて説明してください。
因果関係を断定せず、観察研究であれば交絡、選択バイアス、欠測の影響を明記してください。
結果から言えること、言えないこと、追加で確認すべき事項をそれぞれ3点以内で示してください。
数値は下記の入力値から変更せず、入力にない臨床的判断や治療推奨を追加しないでください。

【統計結果】
ここに合成データで検証済みの集計結果を貼り付ける
```

## 7. AIにコードレビューを依頼する

```text
この解析コードを、統計手法、再現性、欠測値処理、データリーク、乱数管理、個人情報保護の観点でレビューしてください。
まず重大度の高い問題から列挙し、各問題について該当箇所、理由、修正案、修正後の検証方法を示してください。
コードを書き換える場合は、変更前後の統計的な意味が変わらないか確認するテストも追加してください。
実データを読み込まず、合成データで実行できる例に限定してください。
```

## 8. AIの回答を採用する前の確認

1. AIが参照したファイルと列名が正しいか確認する。
2. 除外条件、欠測値処理、分母、イベント定義を解析計画と照合する。
3. 合成データでコードを実行し、エラー・警告・ログを確認する。
4. 既知の結果や別実装と照合し、統計量・図・表が一致するか確認する。
5. AIが作成した文章は、臨床的な断定や治療推奨が混入していないか人が確認する。
6. 公開前に開示統制と`release-manifest.yml`の承認を完了する。

AIは解析者の代わりに研究判断を行うものではありません。コード生成、説明文の下書き、検査項目の洗い出しに利用し、最終判断と成果物の承認は研究責任者が行います。

## 9. 困ったときの依頼文

```text
このエラーの原因を、統計初心者にもわかる日本語で説明してください。
次の順序で回答してください。
1. エラーの意味
2. 起こりやすい原因
3. data/synthetic/ を使った最小再現例
4. 修正案
5. 修正後に確認すべき統計結果とログ
実データや秘密情報を要求しないでください。
```
