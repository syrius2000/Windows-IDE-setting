## 1. 目的

GitHubアカウントを持たない初学者でも、ローカル環境だけで初期セットアップ、Case Project作成、日常の解析作業を開始できることを明確にする。あわせて、Gitの基本操作を順序立てて説明し、将来GitHubを利用する場合への移行方法も示す。

さらに、Cursor Proを導入した統計・RWD初心者が安全にAIへ指示できるよう、合成データを前提としたプロンプトレシピ集を整備する。医師・共同研究者への成果共有については、QuartoとDuckDB-WASMを組み合わせたインタラクティブHTML報告書を標準候補として検証し、外部通信を発生させない配布方式を確立する。

## 3. 文書構成方針

1. READMEは「まず何ができるか」と「GitHubなしでも開始できる」を短く示し、詳細はサブ文書へ誘導する。
2. チートシートは日常操作の入口に限定し、Gitの詳細説明で過密にしない。
3. Git基本文書は、初学者が最初に実行するローカル操作と、共同作業・バックアップ目的でGitHubを使う段階を分離する。
4. `commit`はローカル保存、`push`はGitHub等の共有先への送信であることを明確にする。
5. 実データ、個人情報、パスワードをcommit・pushしない安全規則を既存方針と整合させる。
6. プロンプトレシピは「そのまま使える短い版」と「検証条件を含む安全な版」を分け、AIの回答を採用する前に実行結果・統計量・研究計画との整合を確認する流れを示す。
7. レポートは、分析者側でPython/Rにより生成した集計済み・開示統制済みデータだけをブラウザへ渡す。個票や機微データをHTMLへ埋め込まない。

## 4. インタラクティブ報告書の設計検討事項

### 4.1 目標アーキテクチャ

```text
Python/R/DuckDB
  ↓ 集計・開示統制・検査
Quarto HTML + DuckDB-WASM + ローカルJavaScript/WASM資産
  ↓ 配布
Edge/Chrome（外部通信なし、ブラウザ内フィルタ・グラフ変更）
```

### 4.2 必須検証

- DuckDB-WASM本体、Worker、JavaScriptライブラリ、フォント、CSS、集計済みデータをローカル同梱できること。
- 生成HTMLにCDN、外部画像、外部フォント、分析対象データへの外部送信処理が残っていないこと。
- `file://`でのダブルクリック表示をWindows 11のEdge/Chromeで検証すること。
- `file://`制約でWorkerまたはWASMロードが失敗する場合、外部通信を行わないローカルHTTP起動スクリプトを代替経路とすること。
- ブラウザの開発者ツールでネットワーク要求が外部へ発生しないことを確認すること。
- 集計前にセル抑制、丸め、識別子除去、出力対象列の許可リスト検査を行うこと。
- ブラウザ側に渡すデータが合成データまたは開示統制済み集計データに限定されること。

### 4.3 配布方式の判定

検証結果に基づき、次のいずれかを正式方式として文書化する。

1. **完全自己完結HTML**：ダブルクリックで動作し、すべての資産を同梱する。
2. **ローカルHTTP方式**：同梱した起動スクリプトで`127.0.0.1`だけに配信し、ブラウザから開く。外部ネットワークへは接続しない。

両方式が成立しない場合は、Quarto静的HTMLを正式方式とし、DuckDB-WASMは追加検証課題として切り分ける。

## 5. 検証計画

- Markdownリンクの参照先が存在することを確認する。
- GitHubアカウントなしで読者が開始できる手順になっていることを通読確認する。
- `pull → 作業 → commit → push` の通常フローと、WIP commitをsquashしてからpushする整理フローに矛盾がないことを確認する。
- 既存テストを実行し、文書変更による回帰がないことを確認する。
- Windows上での実行自体はこの文書編集の検証範囲外であることを記録する。
- Cursorプロンプトレシピは、合成データに対する安全な依頼、禁止される実データ依頼、AI出力の検証手順を読者テストする。
- 生成したQuarto報告書をEdge/Chromeで開き、フィルタ、グラフ変更、再読み込み、外部通信なしを確認する。
- `file://`方式とローカルHTTP方式の両方を実環境で比較し、採用方式と制約を記録する。
- WASM・ブラウザ・Quartoのバージョンを固定または記録し、再生成可能性を確認する。

## 7. 実装段階の分離

### 第1段階：文書整備

この計画の承認後に実施する範囲は、README、初心者チートシート、Git基本ワークフロー、Cursor AIプロンプトレシピ集、および関連リンクの整備とする。コード、依存関係、テンプレートの変更は行わない。

### 第2段階：インタラクティブ報告書基盤

第1段階の完了後、別途OpenSpec changeを作成する。そこで次を確定してから実装する。

- QuartoとDuckDB-WASMのバージョンおよび依存関係
- `file://`方式が成立するか、ローカルHTTP方式を採用するか
- データ埋め込み形式と開示統制の責務分界
- フィルタ・グラフ変更の対象範囲
- 外部通信ゼロの検査方法
- Windows 11 Edge/Chromeでの実機検証方法

第2段階の実装・依存関係変更・ブラウザ検証は、第2段階用の計画承認後に開始する。
